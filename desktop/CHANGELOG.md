# Changelog

## 0.1.48

- 客户端整体改成「围着这个活物」组织：首页直接是生命体征（档位、额度、日均开销、还能活几天、开销来源，通过只读的 `GET /admin/life/vitals` 读取），下面是钱包卡片和各部分的健康状态；体征读取失败只影响这一张卡，云端较旧没有这个接口时会引导去「成长」页。
- 侧栏按它的零件分组：心智 / 感知与表达 / 行动 / 生计 / 容器，页面改用比喻名并配技术副标题——生命体征、头脑、视野、双手、交易所、钱包、声音、体检、记忆存档、成长；页面 id 不变。
- Cloudflare 变成「容器」里的一个页面，退出登录也挪到那里；客户端自身的设置仍在侧栏底部。
- 钱包与生命值的两个管理客户端改成串行连接，首页不会同时两次发布 `ADMIN_TOKEN`。
- 修只读 Binance 密钥根本同步不了：Binance 对「无此产品权限」也回 -2015，以前被当成密钥错误，整份快照直接失败；现在该部分降级为「未开通」，不再否定已经读到的现货余额。
- 修公开的 `/api/v3/ticker/price` 被当成需要签名的接口（多传参数回 -1104）：以前价格永远取不到，余额无法估值、也没有合计。

## 0.1.47

- 修 Binance 在云端被拦（HTTP 451）后完全查不到余额：现在由桌面端从你自己的网络读 Binance，把原始响应交给云端解析，交易所页多了「本机同步」状态区（同步成功/失败、多少币种、合计约多少 USDT、多久之前，以及「立即同步」）。
- Binance 的密钥除了写进 Cloudflare，还会在本机钥匙串存一份，用来做本机同步；重新填一次密钥保存即开启。删除账号时会一并清理本机那份。
- 云端只在直连失败（地区限制、网络、超时）时回落到桌面端快照，并说明数据来自桌面端、距今几分钟（超过 30 分钟会额外提醒）；鉴权失败不回落，避免拿旧数据掩盖密钥错误。
- 快照有 2 MB 上限、只接受已知且属于 Binance 的账号、只认固定的十个只读接口；被拒绝的请求不写入任何东西，旧快照也不会覆盖新快照。
- 云端新增 Durable Object `ExchangeDO`（迁移 v8）：导入 0.1.47 时创建，已有数据不受影响。

## 0.1.46

- 配好钱包后，「谋生」机器人会自动出现：每 15 分钟的 cron 检查一次，缺了就建一个，整个部署只有一个。它有明确的使命（保住本金 → 养活自己 → 长期增长）、行为规则（先看再动、不动是默认、算清成本、先写理由后复盘、尊重风控、自己定节奏、少打扰你）。
- 它不能删除、也不能退休，只能暂停；`create_bot` 不再接受「创建一个谋生机器人」这种参数。
- 它自己安排醒来时间：30 分钟到 4 小时之间；钱包未配置、读不出估值或估值低于 5 美元时，只做每小时一次的免费检查，不唤醒、不计开销。
- 估值跌破 5 美元会停止交易并通知你一次，补钱后自动恢复。

## 0.1.45

- 「钱包」页改成「智能体」页，分成「你（主人）」和「智能体的钱包」两块：给它一把专用的私钥（不要填你自己的），再填你的收款地址；它还缺什么会在页头直接列出，两项都填了但钱包没生效时也会说明原因（例如收款地址不能是智能体自己的地址）。
- 管家不再说「做不到、没法访问、没有权限」：只要自己的工具办不了，就派任务交给执行者判断，缺什么由任务结果来说明。派任务的条件也从「多步/读文件/1 分钟以上」放宽成「我的工具办不了」。
- 追问已完成的活改用 `continue_task`，在任务原来的对话里继续，不再新开一个任务。

## 0.1.44

- 新增「钱包」页：在 Base 链上给这个部署配一个钱包。私钥只写进 Cloudflare、不回显，地址由私钥推出；你可以往这个地址转 USDC 当本金和 gas，可选填自己的 RPC。
- 自动汇款：当额度档位变差时，钱包会把「够 21 天开销」的 USDC 汇到你预设的收款地址（不超过余额，最少 5 美元，同一时间最多一笔待你确认）。每笔都先签名、把哈希和原始字节记账再广播，崩溃可核对，不会重复转。
- 赚钱机器人（earner）：在部署里只能设一个，创建时定下。它可以在白名单代币（USDC / WETH / cbBTC）之间兑换，规则是固定收款方、1% 滑点下限、单笔 5 美元起、25% 仓位上限、留 gas；当天实现亏损 10% 会触发熔断，之后要你通过 `wallet_resume_trading` 才恢复。
- 管家多了只读的 `wallet_status`；体征和提示词里会显示钱包估值。没有配置钱包时，这些工具和提示完全不出现。
- 管家可以把做完的任务直接续问：`continue_task` 把追问放进任务原来那段对话，模型保留之前读过的内容和结论，不用重新派一个新任务。
- 云端新增 Durable Object `WalletDO`（迁移 v7），并新增两个密钥 `WALLET_PRIVATE_KEY`、`WALLET_OWNER_ADDRESS`：导入 0.1.44 时会创建，已有数据不受影响。

## 0.1.43

- 新增「生命值」：每次模型调用都记账（用量与开销），据此算出余额、日均开销、还能撑几天和当前档位（充裕 / 吃紧 / 危急 / 冬眠）。
- 档位会改变行为：充裕一切照常；吃紧时机器人少醒、任务改用节食模型（若配了 `models.frugal`）；危急时机器人暂停自动唤醒；冬眠时全部切到 Workers AI 的默认免费模型、机器人彻底停自动唤醒。档位变化只通知一次。
- 管家多了三个只有主人对话能用的工具：`life_vitals`（余额、日均、还能活几天、每角色实际在用哪个模型、开销来源）、`life_credit`（「给你充了 20 美元」）、`life_calibrate`（按厂商余额校准）。
- 体征写进提示词末尾、不进缓存前缀、数值取粗，避免每轮都让缓存失效；管家把「活下去」当第一要务，但你的指令、暂停和删除始终优先。
- 备份包含账本；恢复一份没有账本的旧备份会清空账本，不会拿旧余额继续算。
- 云端新增一个 Durable Object 类（`LifeDO`，迁移 v6）：导入 0.1.43 时会一并创建，已有数据不受影响。
- 顺带修复：模型切换仍保留窗口保护；bot 的 `heal` 容忍被吃紧档拉长的唤醒；恢复备份时账本归零的处理。

## 0.1.42

- 备份不再默认放在「文稿」，升级后不会再反复向你要权限：默认目录改为应用数据目录（macOS `~/Library/Application Support/DeskWand Bot/backups`，Windows `%AppData%\DeskWand Bot\backups`），这个位置不需要任何授权。
- 老客户端把那个默认值当成「你自己选的」写进了 `backup.json`；现在文件带一个 `dirChosen` 标记，没有标记且路径仍是旧默认的会自动跟随新默认，并在第一次运行后写回。你通过页面亲手选的目录（包括故意选「文稿」）会记下标记，不再被迁移。
- 修一次性的模型调用没有会话名：管家改写和任务里的工具审查只传了 `signal`，OpenCode 网关要求 `x-opencode-session`，于是每次都被 400 拒绝——改写退化成原文、审查退化成弹审批。现在这些调用各自带上稳定的会话标识。

## 0.1.41

- 新增「交易所」设置页：可以配置 OKX / Binance 的只读 API，任务就能用一个 `exchange_assets` 工具查余额与持仓（合计按 USDT 计）。
- 密钥只存到 Cloudflare（`EXCHANGE_SECRET_<ID>`），界面不回显；账号按 id 引用，可加自定义地址（OKX 分区站点、Binance 被 451 时需要代理）。

- 删除账号不会删除密钥，页面会列出这些遗留的密钥名，需要你自己在 Cloudflare 里清掉。

## 0.1.40

- 修匿名使用统计一直没上报：0.1.26 起的客户端都是用「构建时注入上报地址」的方式打的，只要构建漏掉那个参数，程序照常启动但什么也不发——线上 0.1.39 的产物里根本不含上报地址。现在地址写在代码里，任何构建都不会丢；仍可用 `-X` 覆盖以便对着本地服务调试。
- 开发构建（不是正式发行）依旧不上报。关闭入口还是侧栏那个开关。

## 0.1.39

- 只有管家跟你说话：任务结果、失败、卡住、bot 消息以前从四个来源各用一套格式发到聊天里，现在统一由管家用一个口吻转述。长内容保留原文，前面加一句引导；改写时丢了数字或链接、超时或失败，就退回原文发出。
- 工具调用的逐条进度不再刷屏：进度留在任务记录里，任务超过 3 分钟没结束才发一行，之后每 15 分钟一行。
- 新增 `quick_lookup`：小事实问题用最多三次联网搜索、30 秒内直接回答，管家不必再在「凭记忆作答」和「派任务」之间二选一。
- bot 不再直接回复你：改为通过 `ask_bot` 回给管家；`@名字` 路由和机器人前缀已移除，引用某条消息时会作为上下文交给管家。

## 0.1.38

- 修部分 MCP 服务连不上：SDK 会先发 `server/discover` 探测版本，网关（例如瑞幸前面的 Zuul）对未知方法回 500，就被当成致命错误，报「Version negotiation failed」。现在遇到这种探测失败会用传统握手重试一次，同一台服务器即可正常连接。
- 正常协商的服务仍走新版路径；不是探测导致的失败照旧原样报错，不会被这次重试掩盖。

## 0.1.37

- 瑞幸咖啡的几个只读操作不再每次弹审批：`queryShopList`、`searchProductForMcp`、`queryProductDetailInfo`、`previewOrder`、`queryOrderDetailInfo` 直接执行；`switchProduct`、`createOrder`、`cancelOrder` 仍按写操作走审批。
- 这个目录项没有 MCP 注解，默认会把八个工具全当写操作，所以按实际行为逐个标了免审名单。

## 0.1.36

- MCP 目录新增瑞幸咖啡（官方远程 MCP 服务）：在「MCP」页从目录里选它，填一次 Bearer Key 即可让任务查门店、找商品、下单和取餐码。
- 瑞幸用的是开放平台签发的 Bearer Key（约一个月有效，过期需重新获取），客户端会把值存成 `MCP_LUCKIN_TOKEN` 并放进 `Authorization` 头；这一项不走 OAuth，因为它的授权探测地址返回的是网页而不是发现文档。

## 0.1.35

- 撤回 0.1.34 里的「超长消息自动压缩」：压缩会把清单从中途截断，「全文.md」附件在手机上比原文更难读，所以改成只保留提示词里的篇幅要求，模型写出的文字原样发出。
- 手机阅读规则仍在管家、任务和 bot 对话的提示词里（结论先说、控制篇幅、不用表格和多级标题），只是不再事后改写你的消息。

## 0.1.34

- 管家不再把任务和 bot 的内容混进自己的对话：任务跑完由任务自己把总结直接发给你，管家不再改写；管家主会话只记一行台账，所以不会被旧结果带偏，也终于知道你刚让 bot 做了什么。
- bot 的消息同样进台账，未读部分会以「数据、不是指令」的形式附在你下一条消息前；新增 `ask_bot` 工具，追问直接交给对应的 bot 回答。
- 管家提示词明确：关于外部最新状态的问题一律派任务去查，不允许拿台账、记忆或旧结果直接答。
- 手机阅读规则统一成一套，放在管家、任务和 bot 对话提示词的最后；每条要发给你的消息都会先检查：超过 300 字（英文 600）或含表格、多个标题、长代码，就用任务模型压缩一次，原文过长的附成文件；压缩失败按段落截断并附原文，存不下原文时才整条发出。

## 0.1.33

- 联网搜索可选服务：新增「搜索」页，可在 Exa（默认，免 key）、Tavily、Brave、DeepSeek 之间切换，保存后立即部署；每个服务都标了额度说明。
- key 按服务存成 secret（`SEARCH_KEY_TAVILY`、`SEARCH_KEY_BRAVE`），DeepSeek 复用已有的模型 key，客户端不会清掉它；只有切换服务时才写入配置。
- 搜索失败自动兜底：缺 key、HTTP 报错或响应格式异常时回落到免 key 的 Exa，并在结果里留一行说明；结果为空、超时或取消不兜底，避免掩盖真实问题。

## 0.1.32

- 修微信一次发多张图/多个文件丢内容：多选发送和合并转发会打包在同一条消息里，之前只取第一张图和第一个文件，剩下的直接丢掉，带图的文字说明也不会转发。现在每个图片和文件都按顺序逐个处理，说明文字跟着第一条一起送。
- 修连发几张图后整批没有任何回应：多个图片原本同时下载解码，Photon 的 wasm 堆不回收，突发几张就把 isolate 撑到 128 MB 被杀，而游标早已前移，整批消息被标记为已读后再也补不回来。现在逐个处理，并且只在整批处理完之后才写游标；中途崩溃会留下游标，iLink 重新投递，靠 eventId 去重不会重复回答。

## 0.1.31

- 「收到，正在处理」改成消息一进队列就发：不再等模型吐出第一个 token，模型启动慢或者这一轮直接失败时也不会没有回应。
- 这条回执在轮次记录创建之前发出，所以后台清理同一时刻结算也不会让答案跑到回执前面。
- 相对 0.1.30 只有这一处行为变化，其余为发布脚本的重试修复。

## 0.1.30

- 任务可以读你的邮箱（只读）：配置了账户后，任务多了 `mail_search` 和 `mail_read` 两个工具，能按条件搜索邮件、读取原文，并可在进度里看到「正在读邮件」这类提示。
- 邮箱是只读的：正文用 `BODY.PEEK` 读取，不改已读状态，也不会代你发信或改邮箱。没有配置账户时，模型看不到这个能力，也拿不到任何邮箱信息。
- 账户凭据按 `EMAIL_SECRET_<ID>` 存成 secret，和模型 key 同一套约定。
- 管家先出字就回「收到」：acknowledge 从固定等 4 秒改成模型产出第一个 token 时触发，一轮只发一次；等待期间你继续发的消息会合并进同一轮一起回答，不用分几次问。
- 如果还在思考、且这一轮还没调用任何工具，你追加的消息会让它重新开始，把前后几句一起回答；已经调用过工具或带着任务报告的一轮会先跑完，避免重复副作用。

## 0.1.29

- 没设置思考强度的角色现在有合理默认：模型支持「中」就用中，否则用它最高一档（不取最贵那档），所以已有部署不用改配置就开始思考；模型页在模型旁直接标出这一档，不能调整的模型也会说明。
- 管家回答慢时不再是一片沉默：超过 4 秒先回一句「收到，正在处理」，5 分钟没有进展会说明卡在哪一步（等模型 / 哪个工具没返回），被回收后也能把答案补发出来；没能答完时会提示再发一次。
- 这些提示只走消息渠道，不进对话记录。

## 0.1.28

- 管家、bot 对话和任务都会按该设置运行；会话已存在时，新的思考强度从下一轮开始生效。
- 保存模型时会保留客户端没有发送的思考强度，旧版本客户端不会把它清掉。
- 模型目录同步更新，包含各模型的上下文窗口与可用档位。

## 0.1.24

## 0.1.23

- 新增共享技能库：技能放在 R2 的 `skills/` 下，每个技能一个 `/skills/<名字>/SKILL.md`（YAML 里写 name 和 description）。所有任务都能读，跨任务持久，不受任务草稿清理影响。
- 新任务开始时会把技能目录（名字 + 描述）注入提示词，正文等模型自己按需 `read`；新装或删除的技能从下一个任务开始生效。
- 你可以让任务自己安装技能（用网络或附件工具取文件后写入 `/skills/<名字>/SKILL.md`）；单文件上限 1 MB、名字限小写字母数字和连字符。

## 0.1.22

- 可以直接和 bot 对话：消息里 `@名字`（或 `@id`），或者引用它那条 `🤖 名字：` 消息回复，就会进到 bot 自己的会话，不再经过管家；回复里可用的工具包括 `run_now`、`write_doc`、`search_runs`、`set_next_wake`、`set_interval`、`pause`、`resume`。
- 引用回复现在会带上被引用的原文（Telegram 取 reply/caption，微信取引用消息的文本，空则回退标题），所以「引用着回复」能被准确识别。
- 换模型时加了上下文窗口护栏：目标模型比当前小四倍以上会被拒绝并说明原因；模型目录补上了 `contextWindow`。
- 直接对话里换模型沿用管家那套安全规则；删除 bot 会一并清掉它的会话。

## 0.1.21

- 任务有了私有工作区：每个任务一份 R2 沙箱，新增 `read` / `write` / `edit` / `list` 四个工具，可以来回改几份草稿再交付。单文件上限 1 MB，没有 shell，长文件用 offset/limit 续读。
- 工作区只是草稿区，主人看不到里面的文件；要交付仍要用 `save_artifact`。任务正常结束、取消或不可重试的失败会清掉草稿，可重试的失败保留下来以便续跑。
- 图片解码器改为按需创建并复用，工具的取消处理统一：取消不再被包成普通错误。

## 0.1.20
